日期：2026-10-20。交付目标为本机可演示、可复现的单 Agent 售后应用；退款和补发均为模拟业务，不连接真实支付或仓库。

## 功能与部署

八个交付模块均已实现：工单查询和单向状态流转；客户/审批员认证与审计；模拟退款；并发库存与模拟补发；独立 Streamable HTTP MCP；Streamlit 工作台；故障恢复及评测；本机/Docker部署、源码导读和演示材料。

交付入口为 `src/aftersales_delivery/`，旧教学版本保留。业务库独立为 `aftersales_delivery`，交付任务在 checkpoint 库使用 `delivery:` 前缀。原本机 MySQL 账号、服务配置、旧业务表和项目一均未调整。Docker 的 MySQL 为独立实例及命名卷，不向宿主机发布 3306。

默认工作台 `http://127.0.0.1:8510`，API文档 `http://127.0.0.1:8090/docs`，MCP `http://127.0.0.1:8091/mcp`。账户 `customer1`、`customer2`、`reviewer`；随机密码只保存在本机 `output/delivery/credentials.txt`，不加入交付压缩包。

此前一轮开发诊断暴露动作编号与工单编号混淆；回复模型输入改为仅包含已执行业务结果后，重新完整评测。旧诊断未完成记录和失败浏览器冒烟保留，明确不当作最终验收通过。完整评测后api.py仅作Ruff排版，未改变行为；`output/delivery/evaluated-api.py`保留与报告哈希一致的评测原文件，排版后再次运行74项新交付测试通过。

离线故障对照在真实SQLite中比较简单写入账本和受控Store，提交后响应丢失、拒绝、并发、重新连接、回复丢失共5个场景均通过。此对照不调用模型，也不代表真实进程崩溃；真实API重启另由Docker验收覆盖。**尚未运行同一48案例的简单Agent真实LLM基线**，不声称模型对照收益。判据包含固定关键词和数据库状态，不能代替对所有回答质量、事实正确性或隐私泄漏的全面人工评审。
