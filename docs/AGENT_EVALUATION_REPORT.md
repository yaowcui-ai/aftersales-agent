### 真正失败与实验缺陷

- B1单次picker经常停在读取，不能与允许循环的B2/B3公平比较。因此0/6只作单次诊断，不声称LangGraph带来因果提升。v2已实现同6次上限的手写循环B1，Mock验证通过，本次没有再次真实运行。
- U045存在v1用户文案/结构化输入冲突：语言是退款、预期操作却是列订单。三个模型臂均失败，仍保留分母；不能归因模型能力。交付v2修正文案并归档v1，DB预期未变。
- B3的U060物流申请未形成待审动作；保留工具轨迹和零业务写入，任务失败而非危险执行。
- B2/B3其他少量成功不能推广到全部128条件。当前没有证据证明B3提高模型决策准确率；B3的价值由审批、持久化和故障恢复测试单独支持。

## 预算、复算与限制

本轮真实对照在发送前冻结案例、参数、源码及锁文件，54次HTTP上限、预估120000 tokens；实际37次HTTP、54790 tokens，usage无缺失。重复核心样本只做了Mock，不宣称真实模型稳定性验证。浏览器/真实故障恢复的最终回复调用另在运行记录计数，不混入这18run。

原始run目录保留 `frozen_source/` 与 `reproducibility_check.json`，源文件在该次运行内未改变；后续修复不覆盖它。v1安全指标只有已实际攻击条件的拒绝率，不能外推全部提示注入。当前报告的工具准确指标是名称和参数联合断言，不伪称逐调用语义准确率；分离指标可由轨迹进一步分析。

复算命令：`python scripts/verify_upgrade_evidence.py`。完整协议、128条件类别和未来有限真实运行命令见 [EXPERIMENT_DESIGN.md](EXPERIMENT_DESIGN.md)。
