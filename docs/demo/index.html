02 / HOW IT WORKS

把模型能力，放进业务约束。

用工具查询事实，用代码执行规则，
用人工审批决定是否提交业务动作。

  1. 01

    用户消息

    提交需求并绑定
    已登录客户身份

  2. 02

    模型工具查询

    经 MCP 查询
    订单、物流、库存

  3. 03

    准备申请

    生成候选动作
    此时不写业务结果

  4. 04

    人工审批

    核对申请与版本
    批准或拒绝

  5. 05

    事务执行

    校验额度与库存
    幂等写入 MySQL

  6. 06

    结果回复

    依据已保存结果
    返回实际工单号

一个 Agent 完成工作流；客户与审批员是不同权限的使用角色。阅读架构与状态设计 ↗

固定 48 个案例，每例重复 3 次，共 144 次真实任务。判据同时检查工具轨迹、审批状态、数据库结果与最终回复。历史完整结果为 129 / 144（89.6%）；历史数字不代表本轮结果。

05 / SCOPE & LIMITS

演示的是工程闭环。
业务范围明确。

本项目基于现有 Agent 服务框架，实现面向电商售后的单 Agent工作流。LangGraph 管理状态和人工中断；独立 HTTP MCP 提供工具；FastAPI 提供接口；MySQL 保存业务状态。

所有订单、退款与补发均为模拟业务。不连接真实支付、商家订单或外部仓储。录屏展示已运行的本地系统；这个公开页面只提供媒体和文档，不托管实时模型或售后后台。

固定案例评测用于工程回归，不能代替真实线上效果、完整隐私审计或生产安全认证。测试和演示的具体覆盖范围以对应记录为准。
